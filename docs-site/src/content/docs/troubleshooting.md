## Starting the app

| Message | Cause | Fix |
| --- | --- | --- |
| OS encryption is not available. Enable the operating system credential store before opening TenuVault. | TenuVault encrypts its saved data with the operating system's credential protection (Windows data protection or the macOS Keychain) and cannot find it. | Make sure you are signed in to a normal user session with the credential store available, then start TenuVault again. |
| TenuVault cannot unlock its saved data. | On macOS, access to TenuVault's Keychain item was denied. On Windows, the data was probably created by another Windows user. | Choose **Quit** and restore access first. Export the key in **Settings** > **Storage and recovery** > **Save recovery key**. **Delete backup key and start over** keeps an unreadable saved-data copy but deletes the backup encryption key from the active app state, along with sign-ins and the license. Backups on this device become unreadable unless you exported their recovery key, and so do Azure backups that an earlier TenuVault version encrypted with it. Azure backups made by this version stay readable. After starting over, use **Import a recovery key** in the same Settings section. |
| Could not load license status | The app could not read its license status during startup. The panel shows the error. A check that does not respond within 30 seconds shows "The license check did not respond. Try again." | Click **Retry**. A spinner appears while the check runs. If the check fails or times out again, the error and **Retry** return. |

## Sign in

| Message | Cause | Fix |
| --- | --- | --- |
| Microsoft did not let this account approve the setup (*code*). | During **Set up with Microsoft sign-in**, the account declined Microsoft's request to approve Microsoft Graph Command Line Tools, or is not allowed to approve it. Nothing was changed. | Select **Try again** and sign in as a Global Administrator, Privileged Role Administrator or Cloud Application Administrator. If you cannot, select **Someone else is the admin? Copy instructions** and send them to your Entra administrator. |
| The app registration is ready, but Microsoft is still making it available for sign-in. Wait a moment, then select Sign in with Microsoft. | The setup created the app registration, and Microsoft's sign-in service did not accept it yet within a minute and a half. | Stay on the **Sign in** step, wait a moment, then select **Sign in with Microsoft**. The IDs are already filled in, and nothing is created twice. |
| Setup did not finish. Cleanup failed. Delete app registration TenuVault Desktop (client id *ID*) in the Entra admin center. | A step failed after TenuVault created the app registration, and TenuVault could not remove it again. The reason follows this text. | Delete the named app registration under **Entra admin center** > **App registrations**, fix the reason and select **Try again**. |
| This tenant does not allow your account to use Microsoft Graph Command Line Tools, the Microsoft sign-in app the setup goes through (*code*). | Microsoft Graph Command Line Tools was removed or blocked in the tenant, or limited to assigned users. Nothing was changed. | Ask your Entra administrator to allow it, or select **Use the setup script instead** and [create the app registration manually](/getting-started/app-registration/#create-the-app-registration-manually). |
| This tenant already has a TenuVault app registration, "*name*" (client id *ID*), but sign-in to its enterprise application is turned off. | An administrator disabled the enterprise application of the TenuVault app registration the setup found. The setup does not add consent to it. Nothing was changed. | Turn sign-in on again under **Entra admin center** > **Enterprise applications** > the named application > **Properties**, or delete the app registration, then select **Try again**. |
| The sign-in in the browser was not completed within 15 minutes. If Microsoft showed an error there, your account may not be allowed to approve the setup. Nothing was changed. | TenuVault waited for **Set up with Microsoft sign-in** and no answer came back from the browser. Microsoft's own error pages, such as **Need admin approval**, do not return to TenuVault. | Select **Try again** and sign in as a Global Administrator, Privileged Role Administrator or Cloud Application Administrator. If you are not one, select **Someone else is the admin? Copy instructions**. |
| Enter a valid tenant ID or domain. | The optional **Tenant ID or domain (optional)** field of the setup is not a tenant ID or a domain. | Correct it under **What the setup does** on the **Connect** step, or leave it empty to use the tenant of the account you sign in with. |
| Delegated permission *permission* was not found on *API*. | The tenant's copy of a Microsoft API does not list a permission TenuVault needs. | Try again after a few minutes. If it stays, [create the app registration manually](/getting-started/app-registration/#create-the-app-registration-manually) and contact support. |
| Graph *method* failed: *reason* | Microsoft Graph refused a request of the setup. Microsoft's reason follows. | Fix the reason and select **Try again**. If TenuVault had created the app registration, it says whether it removed it again. |
| The browser did not open. Open the address above by hand, or run with -UseDeviceCode. | The setup script could not open a browser, for example in a remote shell. | Open the address the script printed in a browser on the same computer. Without a browser there, run the script again with `-UseDeviceCode`. See [Create the app registration](/getting-started/app-registration/). |
| Sign-in was not completed within 15 minutes. Nothing was changed. Run the script again. | The setup script waited for the browser sign-in and no answer came back, for example because the tab was closed. | Run the script again and finish the sign-in in the browser. If the wrong browser opens, copy the address the script prints into the browser or profile you need. |
| Browser sign-in failed. Nothing was changed. | Microsoft answered the sign-in with an error, for example because consent was declined or a Conditional Access policy blocked it. Microsoft's own message follows this text. | Read Microsoft's message, then run the script again. If it reports a device or compliance problem, open the printed address in a browser profile that passes your device identity. |
| The signed-in account *user* lacks a role that can create app registrations and grant admin consent. | The account you signed in with, in TenuVault or in the setup script, cannot create the app registration or cannot grant tenant-wide admin consent. | Start the setup again and sign in as a Global Administrator, Privileged Role Administrator or Cloud Application Administrator. If you activate the role with Privileged Identity Management, activate it first. |
| Setup did not finish. The half-created app registration was removed again. | A step failed after the app registration was created, and the setup removed it again. The reason follows this text. | Fix the reason, then select **Try again** in TenuVault or run the script again. |
| Device code sign-in failed. Conditional Access may block device code flow. | You ran the setup script with `-UseDeviceCode` and Microsoft refused the sign-in. Many tenants block device code flow. | Run the script without `-UseDeviceCode` on a computer with a browser. |
| This PowerShell session runs in ConstrainedLanguage mode, which blocks the browser sign-in this script uses. | PowerShell on this computer is restricted, for example by App Control for Business or AppLocker. | Run the script on a computer without that restriction, or [create the app registration manually](/getting-started/app-registration/#create-the-app-registration-manually). |
| Enter a tenant id or a domain such as contoso.onmicrosoft.com. | The **Tenant id or domain** field is not a GUID or a domain. | Enter the tenant ID or a verified domain of the tenant. |
| The client id is a GUID, printed by the setup script. | The **Application (client) id** is not a GUID. | Copy the client ID from the setup script output or from the app registration in Entra. See [Create the app registration](/getting-started/app-registration/). |
| You signed in to a different tenant. Sign in with an account from this tenant. | The account you used belongs to another tenant, for example a guest account or the wrong browser profile. | Sign in again with an account that is a member of the tenant you are connecting. |
| Microsoft did not return an account for this sign-in. | The sign-in window closed or completed without returning an account. | Try again, and finish the sign-in in your browser. |
| You are not signed in to this tenant. Sign in to continue. | No sign-in is stored for this tenant on this device, or it was made with a different client ID. | Click **Sign in** on the banner, or **Sign in** next to the tenant in **Settings** > **Sign-in**. |
| Your session for *user* has ended. Sign in again to continue. | The cached account is no longer available, for example after the refresh token expired. | Sign in again. |
| Microsoft needs you to sign in again as *user* for *resource* (*codes*). | Microsoft requires interaction for that resource (Microsoft Graph, Azure Storage or Azure Service Management), for example because of Conditional Access, MFA, a password change or missing consent. The codes are the Microsoft error codes, such as `invalid_grant, AADSTS65001`. | Click **Sign in** on the banner and complete the prompt. TenuVault signs you in for the resource named in the message. |
| The app registration has no admin consent for *resource* (AADSTS650057 or AADSTS65001). Add the *permission* to the app registration, grant admin consent, and sign in again. | The app registration does not list the permission, or the permission has no admin consent. Signing in again cannot fix this. It happens with Azure storage when the Azure permissions were left out of the app registration. | Add the permission named in the message (`user_impersonation` for Azure Storage and Azure Service Management, the listed delegated permissions for Microsoft Graph) as described in [Create the app registration](/getting-started/app-registration/), select **Grant admin consent for &lt;your tenant&gt;**, and click **Sign in** again. Backups on this device do not need the Azure permissions. |
| Sign in to access Intune and verify this tenant's license. | Notice on **Backup & Restore**, **Drift Detection** and **Audit Log**: the selected tenant is not signed in. | Click **Open sign-in settings** and sign in. |
| The tenant was not added. *reason* | Adding the tenant failed. The reason follows. | Fix the reason shown, often a license or sign-in issue, and add the tenant again. |

When the first sign-in to a tenant fails with a common Microsoft code, such as a wrong client ID, an unknown tenant, a missing redirect URI, a Conditional Access block or missing consent, TenuVault shows what to do followed by the code. See [Sign-in errors](/getting-started/connect-tenant/#sign-in-errors).

If Microsoft shows an error in the sign-in window itself (an `AADSTS` code), check that the app registration exists in this tenant, that admin consent was granted, and, if the setup script was run with `-AllowedGroupId`, that your account is a member of that group. See [App registration and delegated permissions](/security/permissions/).

If the browser shows `AADSTS50011` (redirect URI mismatch), the app registration is missing the `http://localhost` redirect URI. Add it under **Authentication** > **Mobile and desktop applications**, as described in [Create the app registration](/getting-started/app-registration/), and sign in again.

### After Start over or a reinstall on a new profile

Each TenuVault installation has its own installation ID, kept with the app's saved data. When you choose **Start over** after the saved data could not be opened, or set the computer up again without that data, TenuVault gets a new installation ID. The old one still counts toward the 5 installations per tenant. If a tenant reports that it already has 5 active installations, click **Manage subscription** on the **License** page and release the installations you no longer use in the customer portal.

More on licenses: [Activate and manage your license](/licensing/manage/).

## Backup

| Message | Cause | Fix |
| --- | --- | --- |
| Choose where backups for this tenant are stored in Settings first. | The tenant has no backup storage. | Choose storage in **Settings** > **Sign-in** > **Change storage**. See [Choose where backups are stored](/getting-started/choose-storage/). |
| Choose at least one type to back up. | A custom scope excludes every type. | Select at least one type in the backup scope. |
| The backup could not start. | The backup request was rejected. A more specific reason is usually shown with it. | Check the tenant's sign-in, license and storage. |
| Access denied by Microsoft Graph: *message*. Check that your account has an Intune role and the app registration has the Intune permissions. | Graph returned 403 while reading Intune. | Make sure your account has an Intune role such as Intune Administrator, and that admin consent was granted for the app registration. |
| Skipped *type*: access was denied. The app registration may lack the permission or admin consent, or your Intune role may not allow it. | Microsoft Graph returned access denied for this type. Usually the app registration is missing a permission added in a newer version, the permissions were added as **Application** permissions instead of **Delegated** permissions, or they never got admin consent. Your Intune role can also be the cause. **Backup Details** lists these types under "Left out because access was denied". | Open the app registration in Microsoft Entra, go to **API permissions** and select **Grant admin consent for &lt;your tenant&gt;**, or run the setup script again. Then sign out of the tenant in TenuVault and sign in again. If every permission already shows **Granted**, check that its type is **Delegated**: TenuVault signs in as you and does not use application permissions. Then check that your Intune role covers these items. |
| Could not read *type*: *message* | Reading one type failed. The backup continues and completes with warnings. | Check the message. Retry the backup later if it was a temporary Graph error. |
| Could not read *type*: *host* could not be reached. *guidance* (*code*) | TenuVault got no answer from *host*, usually `graph.microsoft.com`. A proxy, HTTPS inspection, DNS or a firewall stopped the request before Microsoft could answer, so this is not a permissions problem. The code names the cause, for example `ERR_PROXY_CONNECTION_FAILED`, `ERR_CERT_AUTHORITY_INVALID` or `ERR_NAME_NOT_RESOLVED`. `HTTP 407` or an `ERR_PROXY_AUTH` code means the proxy requires a sign-in that was cancelled or refused. | Allow the destinations in [Network requirements](/getting-started/requirements/#network) through the proxy or firewall. For proxy authentication, enter the proxy credentials when TenuVault asks (see [Proxies that require authentication](/getting-started/requirements/#proxies-that-require-authentication)). For a certificate code, make sure the HTTPS inspection certificate is trusted by Windows or macOS. Versions before 0.2.2 did not use the system proxy for Microsoft Graph and showed only "fetch failed"; update TenuVault. |
| Could not back up "*name*": *message* | Saving one item failed. | Check the message and the storage. Retry the backup. |
| Backup failed: no policies could be saved | Nothing could be written. | Check storage access and sign-in, then retry. |
| A different backup is already running for this tenant. Wait for it to finish, then try again. | A backup with another storage account or scope is already running for this tenant, so this request did not start. A scheduled backup that meets this message counts as a failed attempt and is retried. | Wait for the running backup to finish, then start the backup again. |
| Backup folder *name* is already in use by another backup for this tenant and storage. Nothing from this backup was written. Wait for the other backup to finish, then try again. | Another TenuVault instance or automation run claimed the same backup folder first, for example by starting in the same second for the same tenant and storage. This backup wrote no policy files and no summary. | Wait for the other backup to finish, then start the backup again. |
| Backup request timed out after 90 seconds. Check your connection and retry. | A request, token acquisition or response body stayed blocked through three bounded attempts. An exhausted item read or upload is listed as a policy warning and other policies are saved. Token acquisition, listing or manifest commit timeouts fail the job. | Check the network and sign-in, then retry. Scheduled jobs wait 15 minutes before retrying, with at most three attempts per slot. A timeout that fails the job is not counted toward the three attempts if the backup saved nothing, got no answer from Microsoft Graph or Azure Storage, and every failure was a connection failure or timeout. |
| Backup timed out after the 30 minute job deadline. Retry the backup. | The overall job reached its 30 minute deadline before the manifest PUT started, or its commit exhausted the additional two minute budget for requests and retry waits. | Old backups were not removed because the network stopped responding. They will be reconsidered on the next run. | Retention lost contact with backup storage after the new backup was saved. | Check the storage connection. The saved backup remains completed and the next complete run retries cleanup. |
| Could not remove old backups: *message*. They will be reconsidered on the next run. | Storage refused a retention operation after the new backup was saved. The saved backup remains completed. | Check the message, storage permissions and immutability policy. Older backups are reconsidered on the next complete run. |
| Older backups were kept because this backup is incomplete. | Retention cleanup only runs after a complete backup. | No action needed. Fix the cause of the incomplete backup. |
| This backup stopped before it finished, for example because TenuVault was closed. It holds only part of the tenant. | The app closed or the machine slept during the backup. | Run a new backup. The partial backup can still be used for restore. |
| This backup failed before it finished. It holds only the policies it saved and is never used as a complete backup. | The backup stopped after saving some policies, for example because the sign-in expired, Microsoft Graph stopped responding or the deadline passed. | Backup *name* belongs to another tenant. | Shown by **Drift Detection** when one of the two backups to compare names another tenant in its `metadata.json` or ownership marker, for example in a storage account several tenants share. | Select the tenant the backup belongs to, or compare two of this tenant's backups. | N backups could not be read. Select Refresh to try again. | The record of which tenant these backups belong to could not be read, for example because the storage did not answer. They may belong to another tenant that shares the storage account, so they are left out of the list and the Dashboard. | Select **Refresh**. Once the record can be read, each backup is listed again, or left out if it belongs to another tenant. |
| Backups are unavailable. Check this tenant's sign-in, license, and storage access. | **Backup History** could not load. | Sign in again, check the license, and check storage access. |
| This backup was encrypted with a key this device does not have. Import its recovery key. | The backup was made on another device or before a reinstall. | Import the recovery key in **Settings** > **Storage and recovery** > **Import a recovery key**. See [Encryption and recovery key](/security/encryption/). |
| This is not a TenuVault recovery key. Use a TVK2 bundle or a legacy TVK1 key. | The pasted text is not a recovery key. | Paste the full key from the recovery key file, starting with `TVK2.` |
| This folder has backups this device cannot read | The local backup folder holds backups written by another installation with a different key, for example on another computer or before a reinstall, or backup files are damaged or missing. TenuVault found this by reading the tenant's backup inventory, as a backup does. Other backups stay usable and new backups are saved, but nothing in the folder is deleted until this is resolved. | Select **Import recovery key** in the notice and paste that installation's recovery key, or select **Choose another folder** to use an empty folder. See [A folder with backups this device cannot read](/backups/storage/#a-folder-with-backups-this-device-cannot-read). |
| Backup *name* is unavailable: *reason* | Files of this backup in the local backup folder were made with a key this device does not have, are damaged, or are missing. Backup History lists it as **Unavailable**; other backups work as before. | Import the recovery key of the installation that made them, or restore the files from a copy. See [Damaged backup files](/backups/storage/#damaged-backup-files). |
| *N* files in this tenant's backup folder could not be read, so some backups may be unavailable or missing from this list. | Files in the local backup folder could not be read, and some cannot be traced to a backup. | Same fix. ## Background backups

| Message | Cause | Fix |
| --- | --- | --- |
| Scheduled backup of *tenant* failed / Tray backup of *tenant* failed | Desktop notification after a scheduled or tray backup fails. The title identifies how it started. Overlapping tray and scheduled requests for one tenant share the running backup and produce one failure notification. Its title identifies the request that started the backup. The tenant label uses its friendly name, then its domain, then "this tenant". The tenant ID is not used as the label, though the reported error message can contain one.

Scheduled backups also stop when:

* **The machine is asleep, off, or you are signed out.** The background runner only runs in your own signed-in session and does not wake the machine. Locking the screen does not sign you out; closing a laptop lid may put it to sleep. A missed slot runs once at the next start.
* **The sign-in needs interaction.** A background backup cannot complete MFA or Conditional Access prompts. Sign in again when TenuVault shows the banner. If this happens every night, a sign-in frequency policy ends your session (`AADSTS70044`); see [Conditional Access and TenuVault](/security/conditional-access/) for ways to keep scheduled backups running, including the optional [Backup Reader](/backups/backup-reader/).
* **The backup storage is unavailable.** Check the storage messages above.

## Share feedback

Select **Share feedback** in the sidebar, just above **Support**, to tell us what you were trying to do and what got in your way. It is available on every plan, including Community and without a license.

1. Open the screen where you got stuck, then select **Share feedback**.
2. Answer **What were you trying to do?** and **What got in your way, and what would help?** Both are required, up to 500 characters each.
3. Optionally tick **Attach a screenshot of this window**. The screenshot is taken when you open the dialog, so the dialog itself is not in it. It may show tenant, policy or user names, so it is never attached unless you tick it.
4. Optionally enter a **Reply-to email** if you would like an answer.
5. Check **Sent with your feedback**, which lists everything that goes with your answers: the TenuVault version, your operating system and its version, your plan, the section you were on, a random message ID so a retry is not counted twice and, when ticked, the screenshot. Then select **Send feedback**.

Nothing is sent before you select **Send feedback**. Your answers stay in the dialog while TenuVault runs, so you can close it and come back. If sending fails, for example because you are offline or your network blocks `www.tenuvault.com`, the dialog keeps your draft and shows why. Try again later, or select **Copy as email**. It copies the full text (subject, both answers, the same details and the message ID, without the screenshot) to the clipboard and opens a new email to support. The email draft may be shortened to fit what mail apps accept, so if anything is cut off, paste the copied text instead. If no mail app opens, paste the text into an email to support@tenuvault.com.

Feedback and its screenshot are stored up to 12 months; the email copy to support is kept as support correspondence. See [Network connections and data flows](/security/data-flows/#feedback) for exactly what is sent. For a problem that is blocking your work, use **Support** instead.
